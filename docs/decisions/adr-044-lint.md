# ADR-044: 未完成の検査

## コンテキスト

`validateSKAMDocument` は構造の誤り (`errors`) と、後の版で誤りになる書き方の知らせ (`warnings`) を返す。構造として正しくても作業が終わっていないように見える文書は、誤りも知らせも出ずに通る。

- 再読文字の読みが 1 つ。描画は普通の読み仮名と送り仮名として描き、読み上げも再読文字と言わない (ADR-030 R4)。
- 読み仮名、送り仮名、添え仮名が空か空白だけ。
- 竪点が 1 字。
- 傍線の `ref` が、どの ref 注記の `id` にも当たらない。描画はラベルを出さない。
- 返り点が閉じていない。返り点の連なりを解釈するコードは無く、仕様 §7.6 (参考、非規範) にも閉じ方の規則は無い。

playground は parse の例外だけを出し、例外が出るとプレビューを消す。

## 利用者の決定 (2026-10-21)

1. 最初の版に入れる検査: 読みが 1 つの再読文字、空の仮名と 1 字の竪点、閉じていない返り点、参照先の無い傍線の ref。
2. playground は、プレビューを消さずに診断を一覧で出す。
3. 検査が指摘した playground の例 (下の「結果」) は、この ADR の PR の後に別の PR で直す。

## 決定

### 関数と型と置き場

- `lintSKAMDocument(doc: unknown): LintDiagnostic[]` を `@kanbun-skam/skam` のルートから配る。`LintDiagnostic` は `{ code, path, message }`。コードは個別の定数と合併型 `LintCode` で、値を足すのは minor。
- 型、コード、返り点の系列の表は `packages/skam/src/lint.ts` に置き、`errors.ts` (移行の警告) とは分ける。`lint.ts` は index.ts からも `rendering/kaeri.ts` からも値を import しない (循環を避けるため。系列の表は返り点の字を直に書き、`KAERI` の値と一致することをテストで確かめる)。
- 中で検証しない (parse や validator の後に同じ検証を 2 回しないため)。検証を通っていない文書でも例外は出さず、形の合わない所を読み飛ばす。そのときの診断が正しいとは限らない。
- 入力由来の文字列をキーにする表は `Map` と `Set` で持つ。計算は注記と token の数に対して O(n log n)。
- 結果は `marks[]` の添字の順 (同じ注記に複数あれば、下の表の順)。message は固定の文、path は添字だけで、入力の値を含まない。
- `validateSKAMDocument` と parser は変えない。`warnings` は移行の知らせ、lint の診断は作業の知らせで、どの版でも誤りにならない。

### 検査とコード

| コード                   | 対象                                                       | path                |
| ------------------------ | ---------------------------------------------------------- | ------------------- |
| `SAIDOKU_SINGLE_READING` | 再読文字の `forms` が 1 つ                                 | `marks[i].forms`    |
| `SAIDOKU_EMPTY_FORM`     | `forms` の要素に `yomi` も `okuri` も無い (空白だけを含む) | `marks[i].forms[j]` |
| `EMPTY_KANA`             | 読み仮名、送り仮名、添え仮名の `value` が空か空白だけ      | `marks[i].value`    |
| `TATETEN_SINGLE_TOKEN`   | 竪点の `anchor` が 1 字                                    | `marks[i].anchor`   |
| `KAERI_UNCLOSED`         | 閉じていない返り点                                         | `marks[i]`          |
| `HIGHLIGHT_REF_MISSING`  | 傍線の `ref` が ref 注記の `id` に当たらない               | `marks[i].ref`      |

### 閉じていない返り点の規則

- ブロックごとに、返り点を本文の順 (`position.after` の token のブロックの中の位置。同じ位置なら `marks[]` の順) に見る。ブロックをまたぐ連なりは作らない。
- 系列は一系 (一〜四)、上系 (上中下)、甲系 (甲〜丁)、天系 (天地人) で、系列ごとに独立に見る。
- 系列の先頭の字 (一、上、甲、天) が、前のまとまりの後からそこまでの同じ系列の返り点を 1 つのまとまりとして閉じる。本文の順で `二一`、`三二一`、`四三二一`、`下上`、`下中上`、`乙甲`、`丙乙甲`、`丁丙乙甲`、`地天`、`人地天` の形だけが閉じている。
- 形に合わないまとまりの返り点と、ブロックの終わりまでに先頭の字が来なかった返り点は閉じていない。
- ブロックの最後の字に付いたレは閉じていない (返る先の字が無い)。一レと上レは一 (上) とレを分けて見る。複数の字の返り点 (`㆒㆑`、非推奨) は 1 字ずつ同じ位置に並べたものとして見る。

### playground

- parse と描画の後に、自分の try/catch の中で lint を呼ぶ。誤りのときは診断のパネルを空にする。
- 診断のパネルは DOM に常に置き、「診断 N 件」の見出しと一覧 (`role="status"`、`aria-live="polite"`) で出す。出すのは先頭の 100 件までで、超えたら「ほか N 件」を足す。

## 結果

- playground の 19 例のうち 5 例で `KAERI_UNCLOSED` が 1 件ずつ出た。4 例 (學而時習之、論語、添え仮名、傍線) はレを最後の字「之」の後ろに置いている。書き下しは「之を習ふ」で、同じ playground の「拝而受之」の例は「受」の後ろにレを置くので、例の置き方が誤り。1 例 (複合返り点) は二の無い一レ。例は別の PR で直し、それまでは `lint-samples.test.ts` がこの 5 件を固定する。SKAM-draft §7.6 の例の文「レ点が『之』に付く」も、同じ節の「レ点: 次の token と入れ替え」と食い違うので、同じ PR で直す。
- 例と §7.6 は、ADR-045 でレ点の置き場の規約を決めて直した。
- 1 字の竪点の字に付けた二は AIR に出ない (竪点のグループが token 1 つで区切りが 0 個になり、レ以外の返り点の置き場が無い)。レは出る。`lint.test.ts` の `buildAnnotationIR` (full) のテストで確かめた。描画は直していない。

## 受け入れた限界

- 返り点の規則は現代の訓読の教科書の慣行に基づく簡略な規則で、一次資料で確かめていない。系列は一系が四まで、甲系が丁まで、天系が人まで。系列の交差 (一二と上下が入れ子でなく交わる) は指摘しない。ブロックをまたぐ連なりは閉じていないと見る。
- 検証を通っていない文書での診断は正しいとは限らない。
- playground は 100 件までしか出さない。

## 却下した案

- **validator の警告にする**: 誤りにならない内容を、移行の警告と混ぜない。
- **parser で出す**: XML を通さない文書で使えない。
- **重さの区別を付ける**: 今は 1 段で足りる。
- **中で検証する**: parse や validator の後に、同じ検証を 2 回する。
