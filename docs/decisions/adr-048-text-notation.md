# ADR-048: 手で打つ簡易記法から SKAM 文書を作る

白文に訓点を打つ人が日本語 IME のまま打てる平文の記法を定め、記法から SKAM 文書を直接組み立てる。利用者が手打ちの書き味を求め、記号の差し替えと機能の切り替えを呼ぶ側の設定に置くと決めたためである。本文のカギ括弧（引用）の表し方は決めない。

## コンテキスト

利用者の依頼は「マークダウン風の簡易記法を提供する。記号類は差し替え可能にし、利用しない機能などがあっても成立するようにする。書き味の計画からはじめたい」だった。

当時の入力の手段は SKAM-ML（XML）と JSON だけで、読みと送り仮名を付けるにも `<skam:kun yomi="まな" okuri="びて">學</skam:kun>` と打つ必要があった。

## 利用者の決定 (2026-11-27)

1. 書く場面は、人が手で一から打つこと。既存の訓読文を貼り付ける前提は置かない。
2. 最初の版の注記は、返り点・送り仮名・読み仮名・句読点・改行に、再読文字・添え仮名・竪点を加えた 8 種。
3. 変換は記法から SKAM への片方向だけ。
4. 字の後ろの仮名は送り仮名とし、添え仮名には印を付ける。
5. 空行でブロックを区切り、ただの改行はその位置の改行（linebreak）にする。
6. 記号の差し替えと機能の切り替えは呼ぶ側の設定に書き、文書の先頭には書かない。差し替えられるのは記号だけで、構文は固定する。
7. 記号は JIS 配列と US 配列を参考に選ぶ。
8. 返り点と本文のカギ括弧は、中身から見分けられないので、別の記号にする（「見分けられるわけなくないか？ 別の記号にするかエスケープしかないでしょう」）。
9. 本文のカギ括弧は、後の時代に加えた記号だが、現代の人が読むために使うことは普通にある。引用の注記は記法より後に設計する。

## 決定

- 記法は [docs/skam-text-notation.md](../skam-text-notation.md) に書き、private のパッケージ `@kanbun-skam/skam-text-parser` が読む。記法を SKAM-ML に書き換えず、文字列から直接 SKAM 文書を組み立て、注記の制約の検査は既存の validator に任せる。
- 既定の記号は、日本語 IME のローマ字入力で JIS 配列と US 配列のどちらでも打てるものから選ぶ。返り点 `＜＞`（両配列とも Shift+`,` `.`）、読み仮名 `（）`、範囲の読み仮名の始まり `｜`、再読の 2 回目 `｛｝`、添え仮名 `＋`、竪点 `ー`、escape `＼` `￥`。全角と半角を同じ意味で受ける。送り仮名は記号を使わない。
- `「」『』` は引用のために予約し、書くと誤りにする。本文の字にするには escape する。
- 切った機能は記号を持たず、その記号は本文の字になる。有効な機能の記号、escape、予約の記号の中で、同じか前方部分の組がある設定は、parser を作る時点で誤りにする。
- 結果は文書と診断の組か、診断だけかの 2 通りにする。誤りの診断があれば文書を返さない。診断は記法の行と桁で返す。
- 入力の長さの上限の既定値は 100,000 UTF-16 単位。手元（WSL2、Node.js 24）で `漢` を 1,000,000 字繰り返した入力の parse 1 回が、時間の中央値 2.8 秒、ヒープの増分の最大 771 MB で、決め方の基準（2 秒、512 MB）を超えた。100,000 字では 133 ms、124 MB だった（2026-11-27）。上限を上げる設定は呼ぶ側のアプリが決め、入力の文字列の側からは変えられない。
- 当面は npm に公開せず、changesets の `ignore` に置く（kojiki と同じ扱い）。書き味を実物で確かめる前に公開すると、既定の記号を変えにくくなるため。

### 決定しないこと

- 引用の範囲を表す注記と、その記法は決めない。注記の設計の ADR で決める。
- npm に公開するときの版と診断の code の互換の扱いは決めない。公開を決めるときの ADR で決める。
- 記法の細かい規則（書き込みの順、空白の扱い、診断の code の一覧）は [docs/skam-text-notation.md](../skam-text-notation.md) で決める。

## 却下した案

- **返り点に `「」` を使う**: 両配列で Shift なしに打てる括弧は `[` `]`（IME で `「」`）だけだが、本文のカギ括弧と同じ記号になる。中身で見分ける案（返り点の字 1 つとその後ろのレだけで閉じる括弧を返り点にする）も、`「上」` が 1 字の引用か返り点か決まらない。
- **返り点と読み仮名に同じ `（）` を使い、中身で決める**: `（レ）` が読みの「れ」か返り点か決まらない。
- **記法を SKAM-ML に書き換えてから既存の parser に渡す**: SKAM-ML parser のブラウザ版は DOM の parser を使い、Trusted Types の対象になる。平文の記法に DOM は要らない。診断を記法の位置で返すには、XML の位置から記法の位置へ戻す対応表も要る。
- **本文のカギ括弧を、最初の版では本文の字にする**: 引用の注記を足したときに、同じ文字列から違う文書ができる。
- **本文のカギ括弧を句読点（`kind: "other"`）にする**: 範囲を囲む記号なのに、開きと閉じの対が失われる。
- **構文も差し替えられるようにする**: 利用者の決定 6 のとおり、記号だけを差し替える。構文を自由に定義できると、記号どうしがぶつからないことを parser を作る時点で確かめられない。

## 受け入れた限界

- 既定の記号が IME で変換なしに打てるかは、Microsoft IME と Google 日本語入力の既定のローマ字表についての知識によるもので、実機で確かめていない。かな入力や記号を半角で出す設定では出力が変わる。全角と半角を両方受けるので、多くは吸収できる。
- 竪点に長音の `ー` を使うので、本文に長音を書くには escape が要る。
- 字の後ろの仮名を送り仮名にするので、仮名を含む本文（和文の混じる文）は escape するか、送り仮名の機能を切って書く。
