# ADR-045: レ点の置き場

## コンテキスト

ADR-004 は返り点を字と字の間の位置 (`position.after`) に置くと決めたが、レ点を上の字と下の字のどちらの後ろに置くかは決めず、独立した作業として残した。却下した案 A の説明には、「レ点は下のトークンの後に書く」という以前の XML の慣例がある。

リポジトリには 2 通りの置き方があった。

- 上の字の後ろ (`習<レ>之`): playground の「拝而受之」「春暁」などの例、README.md の XML の例、描画と読み上げのテスト、KanbunKundoku 由来の文書。
- 下の字の後ろ (`之<レ>`): 學而時習之の例 (playground の 4 例、README.md の JSON の例、SKAM-draft の付録 A と付録 E、SKAM-ML-draft の傍線の例)。SKAM-draft §7.6 の例の文 (「レ点が『之』に付く」) は、同じ節の手順「レ点: 次の token と入れ替え」と食い違っていた。

ほかに、原文の字の順を入れ替えた例 (學而時習之 を `學而時之習` と書く) と、返り点が読み順と合わない例 (SKAM-draft 付録 D の「不可不學」) があった。

`lintSKAMDocument` (ADR-044) は、ブロックの最後の字に付くレを閉じていないと見る。playground の 5 例が指摘され、例を直すことにした (ADR-044 の利用者の決定 3)。

描画は返り点を `position.after` の字の後ろに描く。上下の区別をする処理は無い。

## 利用者の決定 (2026-10-21)

1. レ点は、返って読む先の上の字の後ろに置く。
2. playground の「複合返り点（一レ点）」(不可不學) は、本文はそのままで返り点をレ点の連続 (不レ可レ不レ學) に直し、例の名前を「レ点の連続」にする。

## 決定

- kaeri の `position.after` は、その返り点が付く字 (後で読む字)。レ点は上の字の後ろ。一二点や上下点も、その印が付く字の後ろ。
- 規約の例外: 竪点でつないだ 2 字以上の語に付く返り点は、語の中の字と字の間 (竪点の区切り) に置く。今の描画 (竪点の中のレ以外の返り点を区切りに描く) と playground の「孝者所以事君也」(`所<二>以`) がこの置き方。
- 規約は SKAM-draft の「kaeri の書き方」と SKAM-ML-draft §7.2 に書いた。
- 読み順を表すための例 (仕様、README、playground、consumer の検査、それらと同じ内容のテスト) を規約に揃えた。字の順を入れ替えた例は原文の順に戻した。SKAM-draft 付録 D は、二と一レの組が読み順と合う「孝者所以事君也」に差し替えた。SKAM-ML-draft の「將死」は、レを「將」の後ろに置いた。
- 書式を確かめるための fixture とテスト (`kaeri-basic.xml`、`kaeri-all-kinds.xml`、`kaeri-compound.xml`、`invalid-kaeri-kind.xml`、playground の E2E の入力、stringify の書き出しの形を見るテスト、web component の読み上げのラベルのテストの入力、3 字の描画のテスト、`lint.test.ts` の意図的な反例) は、読み順の意味を持たないので直さない。

## 受け入れた限界

- 竪点の語に付く返り点を語の中の字と字の間に置く置き方は、熟語の返り点を 2 字の中間に付ける教科書の慣行に合わせたつもりだが、一次資料では確かめていない。
- 書式を確かめるための fixture は、規約に合わない置き方のまま残る。

## 却下した案

- **下の字の後ろに置く**: 描画では、刷られた漢文で レ が載る 2 字の間ではなく、下の字の後ろに出る。§7.6 の手順「次の token と入れ替え」とも合わない。
- **竪点の語の返り点を、語の最後の字の後ろに置く**: 今の描画 (区切りに描く) と playground の例に合わない。熟語の返り点を 2 字の中間に付ける教科書の慣行 (未確認) とも合わない。
